1 Überblick

  • Kein Träger. Jedes Bit ist ein einzelner IR-Blitz (26 µs oder 21 µs). Der Abstand bis zum nächsten Blitz ist das Bit: 90 µs = 0, 130 µs = 1, 169 µs = Synchron-/Endzeichen.
  • Rahmen: S S S · Flag · Bytes … · CRC · S. Das Flag sagt, ob die Bytes invertiert gesendet werden; die Prüfsumme ist CRC-8/MAXIM. Bestätigt an jedem aufgezeichneten Rahmen und jedem Codeblock.
  • Befehle: Byte 1 ist ein Empfängerfilter (Spur, Fahrtrichtung) plus Untertyp-Bits, Byte 2 ist Typ + Wert: Geschwindigkeit 20 + km/h÷5, Magnetfolgen 40–47, Spuren 17–1E, Funktionen 60–6B (+10 dauerhaft), Stopp/Weiterfahren/Bremsen/Makros/Rückwärts.
  • Reichweite: „Sendeleistung“ ist die Blitzlänge (CV3 + 1 µs), nicht der LED-Strom. „Nahbereich“ verkürzt den Blitz von 26 auf 21 µs. „Eigene Distanz“ ist ein Datenbyte in cm.
  • Programmierung: serielle Textbefehle über einen CP210x (38400 Baud, 8E1): Who, Ver, cr (CV lesen), cW (CV schreiben). CarManager schreibt fertige Codeblöcke in drei Befehlsslots; das Modul spielt sie nur ab. Deshalb lässt sich jeder gültige Befehl senden, auch auf getrennten Kanälen.

2 Physikalische Schicht

Gemessen an den LED-Anschlüssen (Rigol DS1104Z Plus, 10 MSa/s, 1,2 s Speicher). Bei 100 ns pro Abtastwert wäre ein 38-kHz-Träger mit rund 260 Werten pro Periode sichtbar; sein Fehlen ist eine direkte Beobachtung.

Wiederholung

  • Ein aktiver Befehl wird ununterbrochen wiederholt: etwa 75–100 gültige Rahmen pro 1,2 s.
  • Ein 3-Byte-Rahmen hat 25 Bit und dauert rund 3,4 ms; ein 4-Byte-Rahmen (Rückwärts + Distanz) 33 Bit.
  • Enthält ein Slot zwei verschiedene Codes, wechseln sie sich ab: paarweise im Abstand von etwa 4,9–5,0 ms, danach eine zufällige Pause von etwa 10–20 ms, damit benachbarte Sender nicht dauerhaft kollidieren.

Gemessen wurde die Spannung an der LED, nicht der LED-Strom oder die Lichtleistung. Gleiche Spannung spricht stark für unveränderten Strom; eine Messung mit Messwiderstand oder Fotodiode steht noch aus.

Zwei LED-Ausgänge

Das IR-Mini hat zwei IR-LEDs. Die LED mit der weißen Markierung am Kabel ist laut Handbuch die Stopp-LED. Im Modus „Bremsen + Anhalten (getrennte Kanäle)“ sendet sie Code 1, die unmarkierte LED Code 2 (Messung und Handbuch übereinstimmend).

Referenzimplementierung

def crc8_maxim(data):
    c = 0
    for b in data:
        c ^= b
        for _ in range(8):
            c = (c >> 1) ^ 0x8C if c & 1 else c >> 1
    return c

def frame_bits(cmd):                       # cmd: Befehlsbytes ohne CRC
    data = list(cmd) + [crc8_maxim(cmd)]
    ones = sum(bin(b).count("1") for b in data)
    flag = 1 if ones < 8 * len(data) - ones else 0
    air = data if flag else [b ^ 0xFF for b in data]
    return str(flag) + "".join(format(b, "08b") for b in air)

Magnetfolgen (magnet)

Wirkt, als wäre das Fahrzeug über diese Folge von Dauermagneten gefahren, solange das Modul sendet. Die unteren 3 Bits sind das Polmuster binär, S = 1, N = 0. Ein N-Magnet bedeutet immer „sofort halten“, daher beginnt jedes längere Muster mit S – die führende 1 wirkt als Startbit und kodiert zugleich die Länge.

Makros und Rollende Landstraße

  • macro, Argument 1–14: startet das im Fahrzeug gespeicherte Makro; Bytes BE 03+n (Makro 1 = BE 04 … Makro 14 = BE 11). Makro 1 und 2 sind standardmäßig Blinker links / rechts.

Nicht verwendete oder ungetestete Bytewerte können unbekanntes Fahrzeugverhalten auslösen, bis hin zu Konfigurations- oder Rücksetzbefehlen. Versuche nur mit einem Ersatzfahrzeug mit gesicherter Konfiguration.

6 Zwei Codes pro Slot, getrennte Kanäle

Jeder Befehlsslot enthält zwei Codeblöcke (Code 1, Code 2):

Befehl in CarManagerCode 1Code 2Ausgabe
Anhalten3E 01BE 01abwechselnd; Code 1 mit 21 µs, Code 2 mit 26 µs
Weiterfahren3E 00BE 00ebenso
Bremsen, Makros, Geschwindigkeit, Spuren, Funktionen, Magnetederselbe Code in beideneine Rahmenart
Bremsen + Anhalten (getrennte Kanäle)3E 40BE 02Code 1 nur auf der weiß markierten LED (Halt), Code 2 nur auf der anderen LED (Bremsen)

Bei „Bremsen + Anhalten“ bremst das Fahrzeug zuerst (LED 2) und hält dann am nächsten N-Magneten (LED 1). Fällt nach dem Bremsbefehl der Strom aus, hält das Auto trotzdem mechanisch am Magneten.

Beliebige Befehle pro LED. Das Modul interpretiert die Befehle nicht, es spielt die gespeicherten Blöcke ab. Selbst erstellte Blöcke werden sofort gesendet, auch im Modus mit getrennten Kanälen: Code 1 geht auf die weiß markierte LED, Code 2 auf die andere. Nachgewiesen z. B. mit „Geschwindigkeit 30 km/h“ neben dem Bremscode und mit „Abblendlicht dauerhaft ein“. Die Beschränkung auf Bremsen + Anhalten liegt allein in CarManager. Anleitung: Abschnitt 7.

7 Getrennte Kanäle mit beliebigen Befehlen (Anleitung)

CarManager bietet „getrennte Kanäle“ nur als Bremsen + Anhalten an. Das Modul selbst kennt diese Einschränkung nicht: Es sendet Code 1 auf der weiß markierten LED und Code 2 auf der anderen LED, egal was darin steht. Mit „Direkte Konfiguration“ in CarManager lassen sich die beiden Codes durch beliebige Befehle ersetzen, ohne zusätzliche Werkzeuge.

Vorher lesen: Geprüft mit IR-Mini-Firmware 1.06 auf dem Oszilloskop; die Wirkung auf Fahrzeuge ist noch nicht getestet. Vor dem Ändern eine Sicherung in CarManager anlegen (Backup, *.clone). CV8 nie schreiben (Werksreset). Das Modul nach der Änderung nicht auf eine neue Firmware aktualisieren, ohne sie vorher zu prüfen.

Schritt 2: Den Slot auf „Bremsen + Anhalten“ stellen

In CarManager für diesen Slot „Bremsen + Anhalten (getrennte Kanäle)“ wählen und übernehmen. Damit stehen in beiden Codeblöcken das Bit für getrennte Kanäle und in den Menü-CVs ein passender Eintrag. Danach werden nur noch die Codeblöcke ersetzt – einer oder beide.

Schritt 3: Werte aus der Tabelle eintragen

Jeder Codeblock besteht aus 6 CVs. Unter „Direkte Konfiguration“ die sechs Werte der Reihe nach in die CVs aus Schritt 1 schreiben (z. B. CV12, CV13 … CV17 für Code 1 in Slot 1). Die Werte sind in Hexadezimal und Dezimal angegeben; alle mit gesetztem Bit „getrennte Kanäle“ und langem Blitz (normale Reichweite).

Schritt 4: Prüfen

  • Die Änderung wirkt sofort, ohne Neustart.
  • Prüfen lässt sich die Wirkung mit einem Fahrzeug im IR-Testmodus von CarManager (Infrarot → Abstandsregelung: das Fahrzeug zeigt den Empfang mit den Blinkern) oder mit einem Oszilloskop an den LED-Leitungen.

Was man wissen muss

  • CarManager überschreibt die Werte, sobald in diesem Slot ein anderer Befehl gewählt wird. CarManager zeigt den Slot vermutlich weiterhin als „Bremsen + Anhalten“ an, weil es seine eigene Menü-CV liest.
  • Die Filter der Feineinstellung (Spuren, Richtungen) nicht mehr ändern: CarManager schreibt dabei alle Codeblöcke neu und ersetzt die eigenen Befehle. Filter besser vorher einstellen; die Tabelle oben gilt für die Werkseinstellung (alle Spuren, beide Richtungen, BE/3E).
  • Getestet ist die Variante mit gesetztem Kanalbit in beiden Codeblöcken (so wie CarManager es bei Bremsen + Anhalten schreibt). Ohne dieses Bit sollten sich die beiden Codes auf denselben LEDs abwechseln, wie bei Anhalten / Weiterfahren (mit beliebigen Paaren noch nicht getestet).
  • Nur Befehle verwenden, die in einer Dauerschleife sinnvoll sind: absolute Befehle wie „Geschwindigkeit setzen“ oder „Funktion ein“, keine Umschaltbefehle (Sonderstatus umschalten).

8 Speicherformat der Codes (Codeblock)

CarManager schreibt jeden Code als Block von bis zu 6 CVs: Kopf, gespeicherte Bytes …, 00-Auffüllung.

Kopf-BitBedeutung
7das Flag-Bit auf der Luft
6langer Blitz (26 µs) wenn gesetzt, kurzer (21 µs) wenn gelöscht; „Nahbereich“ erzwingt 21 µs
5getrennte Kanäle (Code 1 → LED 1, Code 2 → LED 2)
4–3nur im ungeklärten Platzhalter 7A gesehen
2–0Anzahl Bytes (Befehlsbytes + CRC)

Gespeicherte Bytes = Bytes auf der Luft, invertiert. Gleichwertig: Daten = gespeichert XOR (FF bei Flag 1, sonst 00). Beobachtete Köpfe: 03 23 43 44 C3 E3 (plus 7A).

Beispiel: Anhalten, Code 1 = 03 3E 01 AF 00 00; Code 2 = C3 41 FE 7F 00 00 (Flag 1, langer Blitz, Daten BE 01 80).

Beim Wechsel der Kategorie schreibt CarManager zuerst einen Platzhalter (43 BE FF EB, einmal 7A C4 AB) und dann den eigentlichen Code. Die Bedeutung der Platzhalter ist unbekannt.

DCC über IR

Die IR-LED wird direkt vom DCC-Gleissignal getrieben (ohne Träger), Reichweite etwa 20–30 cm; Fahrzeuge sind damit adressierbar. CarMotion-Fahrzeuge unterstützen das im Kompatibilitätsmodus (pro Fahrzeug einzuschalten; in Firmware 1.44 defekt, ab 1.48 wieder korrigiert).

12 Eigenes offenes Modul („Maxi“)

Parallel zur Analyse entsteht ein offenes IR-Modul auf ESP32-Basis (Prototyp: ESP32-C3, 2 Kanäle; Ziel: 8 Kanäle). Es erzeugt die Rahmen per Hardware-Timer (RMT, 1 µs Auflösung) und wird über das offene Netzwerkprotokoll MRRoIP gesteuert.

  • Verifiziert: Ein C-Encoder erzeugt jeden aufgezeichneten CarManager-Block exakt (37 Prüfungen); die Ausgabe des Moduls ist auf dem Oszilloskop Blitz für Blitz identisch mit dem Original (26,0 / 21,0 µs).
  • Pro Kanal eine Befehlsliste, die reihum gesendet wird (z. B. Geschwindigkeit + Licht), mit zufälliger Pause wie beim Original. Blitzlänge pro Befehl (normal / Nahbereich).
  • Direktbetrieb: Der Master sagt, was ein Kanal sendet: {"ch1": [{"cmd": "speed", "arg": 30}, {"cmd": "function_on", "arg": 0}]}.
  • Profile: gespeicherte Steuernachrichten mit Namen, die mehrere Kanäle zugleich setzen, z. B. für Kreuzungen: {"profile": "ns_go", "actions": {"ch1": [{"cmd": "continue"}], "ch2": [{"cmd": "stop"}]}}. Aufruf per Name oder Nummer; nicht genannte Kanäle bleiben unverändert. Ohne Master gilt ein Startprofil.
  • Konfiguration und Steuerung als typisiertes JSON; das Modul prüft jeden Befehl beim Speichern.

Das Projekt baut nur Infrastruktur (Sender, Scanner, Netzwerkanbindung) und keine Fahrzeuge. Software unter Apache-2.0-Lizenz.
